Release 1.43.0: read a folder from the chat

`/ls [folder]` lists one folder of the topic as buttons, folders first.
`/view <file>[:line]` opens a file with line numbers, forty lines at a time,
with a `More` button for the next page. `app.mjs:412` and `app.mjs 412` both
open at line 412: a path pasted out of another app carries a colon, a path
typed on a phone carries a space.

Both read through the fence `/find` already uses — nothing outside the topic
folder, nothing binary, nothing over 512 KB — and `/ls <file>` opens the file
instead of complaining that it is not a folder.

Pressing a folder replaces the card with that folder, so walking back is
`/ls ..` rather than a stack of messages. Rows carry a number, not a path:
callback data is capped at 64 bytes and a path is longer than that, so a card
from an older listing answers "run /ls again" instead of opening whatever
moved into that place.

Unlike `/find`, neither command falls back to the install folder: a topic with
no `/cd` is told to bind one rather than listing the bridge's own directory.

Fourteen tests cover the listing order, the fence, the line parsing, the cap,
the stale card and the no-folder answer. The full suite is 919 passing.
